# QQ 群绑定与奖励活动

管理员侧栏「QQ 活动管理」对应 `/admin/qq-activity`。用户侧栏不显示「小白教程」和「QQ 群活动」，右上角保留「小白教程」入口；`/beginner` 与 `/qq-activity` 保留直达访问，供教程链接、绑定状态和奖励查询使用。沿用现有登录、管理员权限、操作审计和后台访问限制。

## 管理配置

总开关：开启 / 关闭。关闭保留绑定、查询、资格和已经成立的奖励，暂停入账；重新开启结算待发奖励，不移动活动首次开启时间。结束一期是服务端的不可逆状态，普通管理页只提供可恢复的开关。

四项配置分别控制新人体验额度发放、邀请余额发放、群成员自动匹配绑定、群内提示。前两项关闭期间仍保留符合条件的待发记录。自动绑定关闭时仍登记入群及邀请证据，已绑定账号仍按规则核验奖励，其他成员可发送「绑定」。群提示关闭后清空待通知队列并停止产生新通知，重新开启不会补刷旧提示。

金额固定为 $2，资格等级固定为 16 级（一太阳）。管理页支持查看/搜索成员、匹配状态、脱敏记录导出、重试待发奖励、登记可核验的邀请证据。邀请证据人工确认不豁免受邀人的入群、绑定、等级条件。

## 绑定和奖励

- 等级不影响绑定。精确查找数字 QQ 对应的 `QQ@qq.com` 注册邮箱；无邮箱匹配时精确查找等于纯 QQ 号或完整数字 QQ 邮箱的用户名；两种格式归一到同一 QQ。冲突、停用账号不自动绑定。
- 匹配成功直接绑定，不要求 QQ 邮箱验证、确认链接或确认码。官网已有数字 QQ 邮箱注册账号时优先使用该账号；只有没有该注册账号时，才使用纯 QQ 号或完整数字 QQ 邮箱形式的用户名。
- 后台每次活动轮询会静默核对未绑定的在群成员：已注册账号、后续注册账号和保存个人资料后的用户名均可自动匹配，无需额外发送「绑定」。该命令仍保留为立即重试入口；自动绑定开关关闭时可用命令办理。
- 注册邮箱、QQ 号或 QQ 邮箱形式的用户名及已建立的 QQ 绑定共用数据库唯一归属，同一 QQ 不能被不同官网账号重复占用。忽略大小写和首尾空格；并发改名、改名与注册并发也由唯一约束仲裁。自己的邮箱和用户名填写相同 QQ 不冲突。已绑定 QQ 的归属不会随改名或账号删除释放。冲突提示为“该 QQ 号或 QQ 邮箱已被其他账号使用，请使用本人尚未关联的 QQ。”。
- 真正新加入且新注册的成员，自己达到 16 级后发放 $2 使用余额。初始化前任一网站身份或群身份均永久排除个人新人奖励，后续改名、退群重进或重试不能绕过。
- 受邀人活动期间入群、完成绑定并达到 16 级，邀请人可获得 $2 邀请余额；邀请人本人不限等级，网站已有用户也能邀请。受邀人已有网站账号不排除邀请奖励。实际邀请人尚未绑定时先登记待领，绑定后结算。
- 邀请归因只接受已核对的 NapCat v4.18.41 直接邀请事件，或管理员核验的真实证据。入群审批管理员不等于邀请人，无法确认时保留待核验。
- 群成员首次登记历史永久保留。活动开始前已在群里的成员、已经登记后退群重进的成员、换到另一活动群的同一 QQ，均不能建立新的邀请奖励。首次入群尚未满足等级或绑定条件的原始邀请仍可后续结算；重进群不能替换最初邀请人，管理员只能补充首次入群的缺失证据。
- 一个 QQ 与一个网站账号一一对应。奖励按受邀 QQ 和网站账号双重去重，数据库事务将余额、流水、奖励状态一次提交。已有站内推广关系、充值返佣和邀请余额转余额条件保持独立。

群命令支持「绑定」「绑定状态」「邀请奖励」「活动帮助」，「解绑」「更换绑定」提示联系管理员。重复绑定显示“你已经绑定官网账号：脱敏邮箱”。绑定成功只显示“绑定成功！已关联官网账号：脱敏邮箱。”，重复绑定只显示“你已经绑定官网账号：脱敏邮箱。”，不附加奖励资格、待发放或历史已领取说明。“绑定状态”只展示绑定状态和账号。只有奖励从待发放实际入账时，才以奖励流水编号生成一次独立到账通知，显示实际赠送的 $2 体验额度或 $2 邀请余额；重复绑定、重复事件、退群重进不会生成新的到账通知。所有活动邮箱、邮箱形式用户名、导出和提示均脱敏。模板集中在 `backend/internal/qqactivity/prompts.json`。

## 部署与初始化

迁移 `248_qq_activity.sql` 新增活动表，`249_qq_activity_identity_owners.sql` 增加统一 QQ 归属表和用户资料/绑定写入约束。249 在写入前检查存量跨账号冲突，存在冲突则停止迁移，不任选账号或覆盖绑定。由 control 官方迁移入口执行，先完成真实应用数据库的备份并验证 `pg_restore -l`，不手动登记迁移。

构建桥接程序：在 backend 目录运行 `CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -o /tmp/qq-activity-bot ./cmd/qq-activity-bot`。安装到 `/opt/qq-activity/qq-activity-bot`，使用独立低权限用户和随附 systemd 服务；私有配置与两个随机凭据放 `/etc/qq-activity`，仅服务用户可读。网站凭据副本为 control 的 `pricing.data_dir/qq-activity-bridge.token`，使用随机至少 48 字符值，不放 Git、前端或日志。

配置例子见 `deploy/qq-activity/config.example.json`。所有桥接地址仅允许 loopback，群号和已知机器人名单显式指定。先运行 `--probe` 做只读连接检查。首次上线将 `initialize_and_activate` 设为 true 后启动：先连事件流，再完整读取群信息与全部成员，两次群人数与名单长度一致后，在单一数据库事务中记录所有群成员和所有网站账号、匹配候选并开启。初始化静默，不发奖励。再次启动读取已开启状态，不重复初始化或覆盖基线。

等级读取 `get_stranger_info.qqLevel`，不用群成员列表的 `qq_level`。未知等级在 1 / 5 / 15 分钟重试，之后可由本人命令再次触发。成员命令和事件先写入私有持久队列；服务重启重放原事件 ID。WebSocket 超过 90 秒无消息会重连。桥接状态文件 `/var/lib/qq-activity/status.json` 包含连接、控制端就绪和队列长度，不包含邮箱或凭据。通过 `systemctl status qq-activity` 与该文件监控。

断线期间未收到的邀请不能推测补造；保留管理员证据核验入口。群通知发送与确认之间若发生网络中断，提示可能重复，但奖励事务不会重复入账。尚未用真人测试账号验证新入群、邀请人的完整 QQ 客户端链路；独立 PostgreSQL 测试覆盖奖励、归因、并发、关闭重开、免验证自动绑定及跨字段唯一性场景。

## 停用与回退

日常暂停优先使用后台“关闭活动”，保留绑定和账本。服务回退先停 `qq-activity.service`，保留 `/var/lib/qq-activity` 与凭据，再用五节点发布回退恢复应用二进制。新增表保持原样，已发余额不通过代码回退自动扣除。NapCat 登录数据和已有官方 QQ 机器人服务不得覆盖或删除。

个人资料兼容：在「用户名」填写纯 QQ 号或完整数字 QQ 邮箱均可；注册 QQ 邮箱始终优先。迁移 250 扩展迁移 249 的统一归属函数，QQ 号、QQ 邮箱用户名、注册 QQ 邮箱和永久绑定共用唯一性约束，大小写和首尾空格归一；不同账号并发占用时只允许一个成功。
