# 回源健康保护与 ICMP 观测

后台「系统设置 → 多节点 Responses 分流」分别显示回源就绪、ICMP 观测、保护原因和冷却截止时间。`packet_loss_*` 设置及运行态字段保留原名以兼容现有客户端；字段名不代表触发原因一定是 ICMP。

## 当前判断依据

控制节点以 GET 请求源站 `/health/ready`，要求 HTTP 200、`status=ready`，且数据库和 Redis 检查均为 `ok`。单次超时 1 秒，失败后立即复核一次。两个检查均失败时确认回源故障；一次瞬时失败后复核成功不触发保护。探测在后台执行，调度读取不等待探测完成，也不会调用付费模型接口。

默认 `icmp_pause_mode=observe`，ICMP 只告警，不改变路由。只有显式选择 `legacy` 时，持续 ICMP 丢包才参与暂停。另有监控健康和流量配额保护，各自保留独立原因与优先级。

## OVH 发布与恢复

OVH 的源站故障不创建固定冷却记录。发布重启期间若源站暂未就绪，海外请求安全回退到其他节点，状态显示「回源未就绪，恢复后自动接流」；新鲜就绪检查恢复后，自动恢复配置的海外比例，不需要等待普通节点的冷却时长，也不进入 5%/25%/50% 恢复阶段。

原有 OVH 回源暂停记录在下一次运行态计算中移除，控制重启不再恢复这类长冷却。状态存储暂不可用时，仍按当前源站就绪判断，不继承旧的 OVH 回源截止时间。监控过期、流量配额、手动海外比例为 0 等独立限制继续生效。`legacy` 模式下真正由 ICMP 触发的暂停保留其冷却规则。

普通池 `target_weight=0` 是 OVH 海外专用节点的正常配置；海外配置为 `ovh_geo_percent`，生效值为 `ovh_geo_effective_percent`，管理页单独显示，不能据普通池零权重判断人为关闭。

## 普通节点冷却与状态原因

普通节点确认回源故障且存在健康替代节点时进入冷却，仅将生效权重降为 0，保留目标权重。冷却为 1–120 分钟，默认 5 分钟；真实线上值须读取配置。修改用于下次触发，健康检查成功不会提前结束既有冷却。到期后要求新鲜连续健康结果，再经过至少每 30 秒一次的 5%/25%/50% 恢复阶段；再次失败重新冷却。

运行态 `protection_cause` 区分 `origin_health`（回源就绪失败）、`icmp_packet_loss`（持续 ICMP 丢包）和 `unknown`（无法确认来源的历史记录）。回源冷却使用 `auto_disabled_origin_health`，OVH 临时未就绪使用 `origin_unavailable`，ICMP 暂停才使用 `auto_disabled_packet_loss`。界面把观测 ICMP 丢包率单独标注「仅告警」或「参与保护」，不会把 0% ICMP 与回源故障混为同一结论。

普通节点冷却截止与触发样本持久化于 `gateway_routing_packet_loss_state`，按监控地址、节点 ID、源站地址隔离，重启继续生效。状态存储失败时保留上次确认的普通节点保护。无需数据库结构迁移。

## 仅 legacy 模式使用的 ICMP 判断

控制节点读取当前监控地址的 `/api/records/ping?uuid=…&hours=1`，使用原始 ICMP 探测记录。每个 `task_id` 代表一个独立探测目标，至少需要两个目标，多数票通过（3 个目标需 2 个，4 个目标需 3 个）。`value < 0` 为失败，`0` 是成功的亚毫秒探测。首页一小时汇总丢包率不作为触发依据。

一个目标符合以下任一条件才算持续严重丢包：

- 最近两次连续探测均失败。
- 最近 6 次探测构成前后两个各 5 次的滑动窗口，两个窗口均至少失败 2 次（40%），且最近两次仍有失败。

多数目标符合上述条件，且另有探测恢复、监控新鲜、未被流量保护摘除、未在暂停中的正权重节点，才新增暂停。多个节点或探测目标一起异常而没有健康替代时显示「暂无健康替代节点」，避免集体摘流。

样本按时间排序并去重，剔除空值、其他节点记录和超过当前时间 15 秒的记录。相邻样本间隔须为配置探测间隔的 0.5–1.5 倍；最新样本年龄不得超过探测间隔的 2.5 倍且最多 3 分钟。缺测和监控 API 错误不作为丢包。支持 5–300 秒间隔的 ICMP 任务，其他任务不参与投票。当前监控每 60 秒探测一次，持续全丢包通常在第二个失败样本后触发；控制运行态缓存 30 秒、边缘缓存默认 15 秒带来额外传播时间。


真正的 ICMP 暂停要求完整等待冷却到期，并有多数探测目标连续三次成功且无目标仍持续严重丢包；源站健康本身不能解除 ICMP 暂停。重复读取同一批样本不会延长截止时间。

## 验证

回归覆盖 OVH 重启失败→20 秒后就绪→控制重启、既有回源记录移除、状态存储异常、真实不可用安全回退、独立配额/监控限制、legacy ICMP 暂停，以及原因与界面显示。发布时先更新控制节点，使新策略生效，再重启 OVH；观察实际重启窗口与恢复后的海外生效比例，不额外制造故障或付费请求。
