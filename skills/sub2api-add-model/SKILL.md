# Sub2API 新模型：上游优先

在隔离 worktree 中从最新 `main` 开始；保留操作员目录里的其他未提交文件。
先 fetch `origin/main` 和最新版本 tag，检查官方上游是否已经包含精确模型 ID。
如果已经包含，合并官方实现，**不要**保留早期本地补丁、静态价格覆盖、
额外的模型清单或例外政策。官方模型目录、价格与计费优先级、缓存写入、
Codex/OAuth 转换、白名单与客户端配置应作为整体合并；现存账号/分组的显式设置不自动改写。
`codex-auto-review` 的账号白名单和模型映射规则不得附带改动。

此前 GPT-6 Sol/Luna 的本地 `supplemental` 生成器及“缓存写入免费”例外
只适用于上游尚未提供它们时的临时版本。上游 v0.2.8 已提供这两个型号，
此生成器已移除；**不得重新运行或重建该生成器覆盖上游代码**。
后续版本如上游变更模型定义，仍以当时的上游代码及测试为准。

如果上游尚未支持目标型号，先从官方模型页和价格页核对精确 ID、
上下文限制、reasoning、输入/缓存读取/缓存写入/输出费率、服务档和长上下文规则；
记录核实时间及来源。只在上游缺失的部分做最小、本地可回滚的补充，
不能从其他型号推测价格、权限或端点能力。补丁要覆盖默认目录、两套价格兜底、
动态目录、前端白名单、客户端配置以及对应测试；上游随后支持时应移除临时补丁。

使用相同输入分别验证升级前、升级后、独立副本回滚后的行为，保留哈希、
差异、命令、原始 stdout/stderr、退出码及可执行回滚脚本，证据置于仓库外。
模型有名字不代表上游账号有真实调用权限。运行定向模型/价格测试、完整 Go 测试、
前端 Vitest、类型检查与构建；Mac 链接若遇 `arm64e.x1`，使用 `CGO_ENABLED=0`，
不要改系统 SDK。

按 `sub2api-vps-release` 完成隔离分支测试、提交、合并 `main`、推送 `cdy/main`
并回读 SHA。代码交付与生产发布分开；只有用户明确授权发布时才执行五节点发布。
